## 1. 自動ロックの発動

- [x] **無操作でロックされる**: 日記を開いたまま設定した秒数だけ触らずにいると、画面がロック画面に切り替わる
  - 自動化: manual（無操作の経過を待つ必要があり、E2E では自動ロック無効化 (NIKKI_AUTOLOCK_DISABLED) で避けている挙動そのもののため）
  - 既定 (自動ロック 5 秒 / Face ID で解除オン) のまま、ホームで無操作にして 5 秒強でロック画面になった
  - 2026-08-22 自動ロック機構の内部変更 (無操作起点を再描画を起こさない参照型に変更、issue #86) 後に再確認。iOS (5 秒設定) はホーム放置でロック画面になり (https://pub-7f3469dd3e2e445b9b8ec2d1381b5ea8.r2.dev/bannzai/nikki/20260822/72d70b6c-323f-4ccf-8589-d7545c1eb8c7.png)、macOS (30 秒設定) もホーム放置でロック画面になった (https://pub-7f3469dd3e2e445b9b8ec2d1381b5ea8.r2.dev/bannzai/nikki/20260822/16343ba6-6e2d-475a-b555-54a619c17a08.png)
- [x] **タップ操作中はロックされない**: タップを続けている間はロック画面が出ない
  - 自動化: manual（操作を続けながら経過時間を見る確認のため）
  - 自動ロック 30 秒に設定し、1.4 秒間隔のタップを 28 秒続けてもロック画面が出なかった
- [ ] **本文入力・スクロール中もロックされない**: 本文の入力やスクロールを続けている間もロック画面が出ない (入力は編集中の本文 (draft) の変更監視、スクロールはジェスチャというタップとは別の延長経路)
  - 自動化: manual（操作経路ごとに続けながら経過時間を見る確認のため）
  - ⏭️ スキップ: 今回の確認はタップ経路のみ実施。入力・スクロール経路は次回 QA で確認する
  - 2026-08-22 入力経路の部分確認: 自動ロック 30 秒設定の iOS で、かなキーの 2 秒前後間隔のタップ入力を続けている間はロックされなかった (キーボードタップは画面タッチとして拾えないため、本文の変更監視が延長経路として機能している)
- [x] **自動ロックの秒数が反映される**: 設定でロックまでの秒数を変えると、次のロックがその秒数で発動する
  - 自動化: manual（設定変更後に無操作の経過を待つ確認のため）
  - 5 秒から 30 秒へ変更後、最後のタップから 13 秒時点ではロックされず (5 秒設定ならロック済みの時点)、36 秒時点でロック画面になった
- [x] **Face ID で解除がオフならロックされない**: 設定で「Face ID で解除」をオフにすると、無操作のまま放置してもロック画面が出ない
  - 自動化: manual（無操作の経過を待つ確認のため）
  - トグルをオフにして 25 秒無操作で放置してもロック画面が出なかった (自動ロックは 5 秒設定のまま)

## 2. 自動ロックの秒数設定 (設定 > 自動ロック)

設定の自動ロックは confirmationDialog から専用ページ (AutoLockPage) に変更した。プリセット (5/10/30/60秒) は無料、カスタム秒数 (1〜3600秒、1秒きざみ) は Nikki Plus 限定。

- [x] **プリセットを選べる**: 設定 > 自動ロック でプリセットの秒数が並び、いま適用されている秒数にチェックが付く
  - 自動化: manual（一覧のチェック表示を目視で確認する）
  - 2026-08-22 ローカル iOS Simulator (5秒にチェック) と macOS (30秒にチェック) で確認 (https://pub-7f3469dd3e2e445b9b8ec2d1381b5ea8.r2.dev/bannzai/nikki/20260822/bf90e27b-7e7a-4e68-b8b4-a97fea94d4f2.png, https://pub-7f3469dd3e2e445b9b8ec2d1381b5ea8.r2.dev/bannzai/nikki/20260822/6681d6d0-6c91-43f9-b943-2ebd1db25c9b.png)
- [x] **未加入のカスタムはペイウォールへ**: Nikki Plus 未加入のとき「カスタム」行に錠前が付き、タップするとペイウォールが開く。ペイウォールの特典に「1秒きざみの自動ロック」が載っている
  - 自動化: manual（錠前表示とペイウォールの表示を目視で確認する）
  - 2026-08-22 ローカル iOS Simulator で、カスタム行の錠前 → タップでペイウォール(特典2件)が開いた (https://pub-7f3469dd3e2e445b9b8ec2d1381b5ea8.r2.dev/bannzai/nikki/20260822/04e48518-8ffb-4cfa-9147-5e53d02cc0e5.png)
- [ ] **加入中はカスタム秒数を入力できる**: Nikki Plus 加入中は「カスタム」行に秒数の入力欄が出て、1〜3600 の整数を入れるとその秒数が保存され、ロックがその秒数で発動する
  - 自動化: NikkiTests/AutoLockPlusGateTests.swift (effectiveAutoLockSeconds のゲート) + manual（入力欄の操作は加入状態が必要）
  - ⏭️ スキップ: QA 環境で Nikki Plus を有効化する手段がなく (StoreKit テスト構成は Xcode スキーム起動時のみ有効)、加入中の入力欄 UI は未検証。ゲートのロジックはユニットテストで検証済み
- [ ] **失効中はプリセットへ倒れる**: カスタム秒数を保存したまま Plus が失効すると、表示と実際のロックが既定の5秒に倒れる (保存値は残り、再加入で戻る)
  - 自動化: NikkiTests/AutoLockPlusGateTests.swift（実 UI での確認は加入・失効の切り替えが必要なため）
  - ⏭️ スキップ: 加入状態を切り替えられないためユニットテストのみ

## 3. ロック画面の見た目

- [x] **本文が読めない**: ロック中は背景が日記の骨組みだけになり、書いていた本文が読み取れない
  - 自動化: manual（表示の目視確認）
- [x] **ロックの案内文言**: 「手が止まったのでそっと鍵をかけた」旨の見出し・説明と、解除を促す脚注が表示される
  - 自動化: manual（表示の目視確認）
  - 見出し「Locked, just in case」/ 説明「Your hands rested for a while, so we quietly locked the page.」/ 脚注「Unlock to pick up right where you left off」
- [x] **解除ボタンが端末の認証手段に合う**: Face ID の端末で、解除ボタンの文言とアイコンが Face ID に一致する
  - 自動化: manual（端末ごとの生体認証構成に依存する表示の目視確認）
  - Face ID 対応機の Simulator で、Face ID のアイコンと「Open with Face ID」の文言が出た
- [ ] **解除ボタンが Touch ID・パスコードの端末に合う**: Touch ID の端末・生体認証のない端末で、解除ボタンの文言とアイコンがそれぞれ Touch ID / パスコード・パスワードに一致する
  - 自動化: manual（端末ごとの生体認証構成に依存する表示の目視確認）
  - ⏭️ スキップ: Face ID 対応 iPhone の Simulator のみで実施。Touch ID・生体認証なし端末の構成は simulator で用意できず未確認

## 4. ロックの解除

- [ ] **認証に成功すると元の画面へ戻る**: 解除ボタンから認証を通すと、ロック前に開いていた画面がそのまま現れる
  - 自動化: manual（simulator は生体認証もパスコードも未設定のため認証ダイアログが出ず、ボタン押下でそのまま解除される。認証を伴う本来の解除は実機での確認が必要）
  - ⏭️ スキップ: iOS Simulator は生体認証が未登録でデバイスパスコードも未設定のため、解除ボタンから出る「Enter iPhone Passcode for “Nikki”」を通せず、認証成功の経路を再現できない。実機での確認が必要
- [x] **認証をキャンセルするとロックが続く**: 認証ダイアログをキャンセル・失敗させるとロック画面のまま残り、日記が見えない
  - 自動化: manual（認証ダイアログが出る実機でのみ確認できる）
  - 解除ボタン → パスコード入力をキャンセルすると、ロック画面のまま残り本文はスケルトンのままだった
- [ ] **ロック中は背後の画面を操作できない**: ロック中にキーボードショートカット (新規日記・検索) を押しても背後の画面の状態が変わらない
  - 自動化: manual（ハードウェアキーボードからのショートカット操作のため）
  - ⏭️ スキップ: リモート iOS Simulator にハードウェアキーボードを接続できず、キーボードショートカット (新規日記・検索) を発火できない

## 5. macOS のウィンドウ連動

- [ ] **ウィンドウをアクティブにすると認証を求められる**: ロック中の Nikki のウィンドウを前面にすると、ボタンを押さなくても Touch ID の認証ダイアログが出る
  - 自動化: manual（macOS の実機で、Touch ID が登録された Mac でのみ確認できる）
  - ⏭️ スキップ: iOS Simulator では macOS のウィンドウ連動を確認できない
- [ ] **他アプリへ移ると認証ダイアログが消える**: 認証ダイアログが出ている状態で別のアプリを前面にすると、ダイアログが他アプリの上に残らず閉じる
  - 自動化: manual（macOS のウィンドウ操作を伴うため）
  - ⏭️ スキップ: iOS Simulator では macOS のウィンドウ連動を確認できない
- [ ] **最小化でも認証ダイアログが消える**: ウィンドウを最小化すると認証ダイアログが閉じ、復帰時に改めて認証を求められる
  - 自動化: manual（macOS のウィンドウ操作を伴うため）
  - ⏭️ スキップ: iOS Simulator では macOS のウィンドウ連動を確認できない
- [ ] **スクロール・キー入力でも自動ロックが延長される**: macOS でトラックパッドのスクロールやキー入力を続けている間はロック画面が出ない
  - 自動化: manual（macOS のトラックパッド・キーボードの実操作を伴うため）
  - ⏭️ スキップ: iOS Simulator では macOS の入力経路を確認できない
